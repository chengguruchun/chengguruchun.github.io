Concepts · 核心概念

比具体模型更稳定的抽象：从模型能力、上下文与工具协议，一直到 Agent Runtime 的系统边界。

Attention

让模型根据上下文动态决定信息之间的关联强度。

Knowledge Distillation

把 teacher model 的行为或知识迁移给更小的 student model。

In-context Learning

不更新模型参数，仅通过上下文示例改变当前任务表现。

RLHF

利用人类偏好信号对语言模型行为进行对齐。

RAG

把模型与外部可检索知识连接，降低纯参数记忆的限制。

Tool Use

让模型调用搜索、代码、数据库、API 等外部能力，而不局限于生成文本。

MCP · Model Context Protocol

面向 Agent 的通用工具与上下文连接协议，把模型运行时与外部工具、资源、提示能力标准化连接起来。

Agent Protocol

HMS · Model Hardware Standard

从软件工具接口进一步走向物理世界：用统一的能力与设备接口描述硬件，让 Agent 能理解、调用并组合真实世界的执行能力。

Physical AI

Agent Skills

把可复用的任务能力、工具组合、工作规范与执行经验封装成 Agent 可以发现和调用的能力单元。

Skill

Context Engineering

围绕模型当前状态组织信息、历史、工具结果与约束，让下一步生成更可靠。

Tool Gateway

在 Agent 与底层工具、Provider、租户权限之间增加统一的治理层，负责路由、鉴权、隔离与能力抽象。

Runtime

Test-time Compute

把更多计算预算放在推理阶段，通过搜索、验证或多次采样提升任务表现。

Memory

保存任务轨迹、长期知识、中间状态与反馈，让 Agent 能从过去的执行结果进入下一轮决策。

Outcome Evaluation

不只判断模型是否完成了某一步，而是验证最终目标是否真正达成，并把结果反馈给下一轮执行。

Verification

Agent

模型从一次性回答走向感知、规划、行动、反馈与迭代。

Agent Runtime

让 Agent 像服务一样被调度、执行、观测、恢复与验证，是这里正在持续研究的系统层。

How to choose

先选运行形态，再选语言和框架。

构建业务 Agent 应用，可从 OpenAI Agents SDK、Mastra、Google ADK 或 Agno 入手；需要复杂状态、长任务和可恢复编排，重点看 LangGraph 与 Deep Agents；需要角色化团队协作，可看 CrewAI 与 AgentScope；需要直接运行或扩展 Coding Agent，则比较 Pi、Claude Agent SDK、Hermes、DeepSeek Harness 与 DeerFlow。

这些项目的抽象层级不同，不能只按功能数量排名。选型时还应比较模型供应商耦合度、工具与 MCP 接入、状态持久化、权限边界、Sandbox、可观测性、评测和部署方式。
