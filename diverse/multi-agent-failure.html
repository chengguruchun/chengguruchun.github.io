多 Agent 协作的失败模式更像分布式事务

2026-09-01chengguruchunMulti-Agent分布式系统

Question

多 Agent demo 往往「看起来能跑」：角色分工、互相调用、汇总答案。一旦引入共享资源与外部写入，失败模式迅速接近分布式事务——部分成功、重复执行、脑裂决策。

My Thinking

高频失败模式：

  • 无权威真相源：两个 Agent 各自「以为」库存充足。
  • 重试放大器：计划器重试导致工具侧重复下单。
  • 补偿缺失：前方已写入，后方失败却无法回滚。
  • 对话式协调：用自然语言协商替代协议，无法机械验证。

可用的工程对策来自旧世界：幂等键、saga/补偿、租约与锁、单写者原则、显式状态机。多 Agent 编排器首先应是工作流引擎，其次才是「智能」。

Open Questions
  • 什么场景真正需要两阶段提交，而不是 saga？
  • Agent 之间的「协议」能否用 schema + 状态机生成，而不是提示词约定？
  • 如何在 UX 上暴露「部分完成」而不假装端到端成功？
