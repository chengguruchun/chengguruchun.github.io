Agent 记忆：状态、知识，还是日志？

2026-08-22chengguruchunMemory状态管理

Question

「给 Agent 加记忆」常被实现成向量库检索。但系统里的记忆至少有三种角色：短期工作状态、可回放的事件日志、可共享的长期知识。混为一谈会导致一致性事故。

My Thinking

我倾向显式分层：

  • 工作记忆（Working）：当前 Run 的 scratchpad，随会话结束可丢弃或归档。
  • 情景记忆（Episodic）：Run Record / 轨迹，强调时间与因果，用于审计与复盘。
  • 长期知识（Semantic）：经审核的事实、手册、契约；更新需要版本与责任人。

向量检索适合语义层的召回，不该偷偷充当事务状态。需要强一致的，走数据库与工作流引擎；需要解释「当时为什么这么做」的，走日志与轨迹。

Open Questions
  • 跨会话「记住用户偏好」属于哪一层？谁有权遗忘？
  • 多 Agent 共享记忆时，冲突合并策略是什么？
  • 记忆投毒（错误写入被反复召回）如何检测？
