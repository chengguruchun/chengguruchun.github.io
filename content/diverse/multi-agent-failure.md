# 多 Agent 协作的失败模式更像分布式事务

- date: 2026-09-01
- tags: Thinking, Multi-Agent, 分布式系统

## Question

多 Agent demo 往往「看起来能跑」：角色分工、互相调用、汇总答案。一旦引入共享资源与外部写入，失败模式迅速接近分布式事务——部分成功、重复执行、脑裂与真相源争夺。我们该借用哪些分布式系统工具？

## My Thinking

把多 Agent 当分布式工作流，而不是聊天室：

- **幂等与去重：** 每个外部副作用需要幂等键；重试默认会发生。
- **补偿优于幻想 2PC：** 多数工具 API 不支持预备提交；失败要用明确补偿或人工回环。
- **真相源单一：** 共享状态不能由多个 Agent 各写各的「我认为的世界」。
- **超时与隔离：** 慢 Agent 不能无限占用预算；需要取消传播。

协作协议本身就是控制面职责的一部分。

## Open Questions

- 多 Agent 的「事务边界」应画在任务、子目标还是单次工具调用？
- 如何对业务暴露可理解的部分失败，而不是一次性全盘重来？
- 是否需要类似 saga 编排的一等公民原语？
