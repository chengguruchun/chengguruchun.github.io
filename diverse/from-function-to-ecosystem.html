从函数到生态系统：重新理解大模型与 Agent

物理学给我们规律，生态学给我们关系与反馈，科学实验告诉我们如何验证；把三种心智放在一起，可以重新理解 LLM 与 Agent。

思路 2026-09-04发表 2026-09-08作者 chengguruchunPhysicsEcologyLLMAgent

我们习惯把软件系统理解成函数：给定输入，经过确定的逻辑，得到输出。但大模型出现以后，这个直觉开始出现裂缝。我越来越觉得，理解这种裂缝，可以同时借用两种看起来距离很远的学科：物理学与生态学。

一、为什么大模型不像传统函数

传统程序通常可以近似成：

Input
  ↓
Deterministic Logic
  ↓
Output

而一次大模型调用真正依赖的东西更多：Prompt、Context、History、Model、Tools 与 Decoding。更接近：

Prompt + Context + History + Model + Tools + Decoding
                         ↓
                Conditional Distribution
                         ↓
                   One Sample

所以同一个问题换一种上下文组织方式，结果可能改变；换一个示例，分布可能改变；换一个模型版本，行为可能改变。它不是「没有规律」，而是规律更多表现为条件下的概率分布。

真正值得问的问题，不只是「这一次为什么错了」，而是「在什么条件下，它更容易正确？」

二、物理学给我们的启发：寻找可重复的规律

物理学不断从复杂现象中寻找稳定关系。把这种心智迁移到 LLM，工程就不应该只是不断试 Prompt，而应该逐渐变成：

Hypothesis
    ↓
Experiment
    ↓
Observation
    ↓
Comparison
    ↓
Conclusion
    ↓
Next Hypothesis

例如怀疑「规则放在 Prompt 最前面更有效」，就固定模型、数据集和解码参数，只改变规则位置，然后重复采样。结论应该带边界：在数据集 D、模型 M 和参数 Θ 下，条件 A 比条件 B 有更高的成功率，而不是「这个 Prompt 永远更好」。

这也是我认为 Prompt Engineering 会逐渐长成 Experiment Engineering 的原因。

三、但只用物理学的心智还不够

如果只用输入 → 输出理解 Agent，很容易把 Agent 想成一个更大的函数。但当系统开始拥有 Memory、Tools、Multiple Agents、Environment、Feedback、External Side Effects 与 Long-term State，事情开始变化。

生态系统很少存在一个简单的 A → B。一个行为会改变环境，环境变化又反过来影响下一步行为。这与 Agent Loop 非常接近：

Goal
 ↓
Action
 ↓
Environment
 ↓
Observation
 ↓
Gap
 ↓
Adjustment
 ↺

四、Agent 真正复杂的地方，是反馈而不是模型

例如一个 Agent 要「降低工厂能源消耗」：读取设备数据、判断状态、调整设备、观察功率变化、发现温度变化、再调整策略。这里已经不是 Prompt → Answer，而是一个持续与环境交互的系统。

Goal
 ↓
Policy
 ↓
Action
 ↓
Environment
 ↓
Observation
 ↓
Outcome
 ↓
Policy Adjustment
 ↺

Agent 的能力因此越来越像一种环境中的适应能力。

五、概率性并不等于不可工程化

天气是概率性的，但气象学仍然可以工作；生态系统高度复杂，但生态学仍然可以研究。工程目标发生了变化：

确定性系统：
Input → Output

概率性系统：
Conditions → Distribution → Outcome

因此评价 Agent 时，也应该从「这次回答对不对」逐渐走向 Success Rate、Error Distribution、Cost、Latency、Consistency、Held-out Performance 与 Real Outcome。

一次漂亮的回答只是一个样本。真正值得沉淀的是在什么条件下，系统更可靠。

六、Proxy Metric 不等于真实结果

复杂系统还有一个危险：我们很容易把代理指标当成真实目标。

Tool Call = PASS
API Test = PASS
Workflow = SUCCESS
Model Self-Eval = PASS

          ≠

Real Outcome = SUCCESS

因此我越来越倾向于把任务结果拆成三层：Proxy（过程是否正常）、Evidence（是否存在可核对证据）、Outcome（真实目标是否完成）。

七、从 Experiment Engineering 走向 Loop Engineering

科学实验解决「如何知道什么条件更好」，Agent Loop 进一步解决「知道以后，系统如何自己调整」。两者其实是一条连续的路线：

Experiment Engineering
        ↓
Evaluation
        ↓
Policy / Strategy
        ↓
Agent Loop
        ↓
Environment Feedback
        ↓
Next Experiment

这也是我理解 Loop Engineering 的方式：不是把 Workflow 写得更复杂，而是让现实结果成为下一步行动的输入。

八、最终会从模型工程走向环境工程

如果继续往前推，Agent Engineering 的对象会不断扩大：

Model
  ↓
Prompt
  ↓
Agent
  ↓
Runtime
  ↓
Multi-Agent
  ↓
Environment
  ↓
Feedback
  ↓
Evolution

模型仍然重要，但它只是系统中的一个参与者。真正决定系统长期能力的，是模型如何与工具、记忆、其他 Agent 和环境发生关系，以及这些关系能不能形成稳定的反馈闭环。

九、我现在更愿意这样理解 AI 工程

物理学提醒我们寻找规律，生态学提醒我们观察关系，科学实验告诉我们如何验证，而 Agent Engineering 要把这些东西变成可以运行的反馈系统。

所以未来 AI 工程可能不只是 Model Engineering。它会同时包含 Model Engineering、Experiment Engineering、Agent Engineering、Loop Engineering 与 Environment Engineering。

从函数到实验，从实验到循环，从循环到生态系统。这可能是理解下一代 AI 系统的一条重要路径。
