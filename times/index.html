Context Engineering

当可靠性成为默认要求后，真正的瓶颈转移到智能体如何理解并利用上下文。Context Engineering 将提示词、记忆检索和工具信息的设计系统化，直接降低因上下文缺失或冲突导致的失败率。它既是可靠性的前置条件，也是从“能用”迈向“可控”的关键工程实践。

回路设计

每周一次：读状态、提案、过门禁、写入、发布、再观察。周期 YYYY-MM-WN 表示某月第 N 个 7 天（上海时区），不是 ISO 8601 周号。

  1. 01 State 读现状

    当前词、历史、feedback hints

  2. 02 Propose 提案

    3–5 候选 + 结构化证据

  3. 03 Validate 门禁

    结构 / 去重 / 编辑 / 证据 / 相关性

  4. 04 Apply 写入

    只改工作区，一致性检查

  5. 05 Publish 发布

    Autonomous 直推；Review 等人确认

  6. 06 Observe 观察

    run manifest → 下周 Learn

证据必须带 https 来源才能发布。Review 模式会停在 Validate，不改线上词。
